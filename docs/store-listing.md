## Store listing tab

**Name**: Sproutling

**Summary** (from the manifest, 120 of 132 characters):
A pixel pet that keeps your Buffer posting streak company and gently reminds you to stretch and look up from the scroll.

**Category**: Fun (Productivity is the alternative)

**Language**: English

**Description**

```
Sproutling is a tiny pixel pet that lives in the corner of your browser and gets fed by what you post on Buffer. It helps you remember your streak, and when the scrolling goes on a while it's a calm presence with a kind word to stretch, sip some water and look up.

Post something and it perks up. Let your queue run dry and it gets hungry. Disappear for a few days and it takes a nap. It never dies, we're not monsters.

WHAT IT DOES

• Sits in the corner of the Buffer app and shows how your week of posting is going, with five moods and a little animation for each.
• Visits the sites of your connected channels (LinkedIn, X, Instagram, Facebook, Threads, TikTok, YouTube, Pinterest and Bluesky), one site at a time, and only when you allow it.
• Offers a kind word in a speech bubble when you've been scrolling for a good while, such as "Let's pause and reflect on what we've consumed." It starts chatty and eases off, and there's a switch to turn it off.
• Can be dragged anywhere, and remembers its spot on each site. Click it for a small panel with a link back to Buffer and a nap button.

HOW IT WORKS

Connect your Buffer account with Buffer's own sign-in screen. The extension asks for read-only access to your account, posts and ideas, checks in every 15 minutes, and turns what it finds into Sproutling's mood: hit your posting goals and it's full, scheduled posts keep it calm, and a new post, draft or idea makes it eat for a few seconds.

PRIVACY

Everything stays in your browser. There is no server of ours and no analytics. It never posts, edits or deletes anything in your account, and it never records or sends what's on the pages you visit. The full policy is at https://sproutling.pet/privacy

Sproutling is an independent project, built on Buffer's public API for the Buffer Commit contest. The code is open source: https://github.com/andreasvirkus/buffer-feedling
```

## Privacy practices tab

**Single purpose**
Show a small pixel pet that reflects the user's Buffer posting activity, and offer gentle reminders to share instead of scrolling.

**Permission justifications**

| Permission | Justification |
|---|---|
| `storage` | Keeps the sign-in, the pet's state and the user's settings (pet position, nap, nudges) on the device. |
| `alarms` | Checks Buffer every 15 minutes in the background so the pet's mood stays current. |
| `scripting` | Registers the pet's content script only on the sites the user has chosen to let it visit. |
| `offscreen` | Renews the Buffer sign-in. Buffer's token endpoint only accepts requests from our website's origin, so a hidden page frames a small page of ours that makes the request. |
| Host `https://auth.buffer.com/*` | Buffer's OAuth sign-in and token endpoints. |
| Host `https://api.buffer.com/*` | Reads the user's account, channels, posts and ideas, read-only. |
| Optional hosts (the social sites) | Requested one site at a time, when the user taps a connected channel, so the pet can appear there. Used only to show the pet and measure scroll distance. |
| Content script on `publish.buffer.com` | Shows the pet in the Buffer web app. |
| `externally_connectable` (`https://sproutling.pet/*`) | The sign-in page on our site hands the new tokens to the extension. |

**Remote code**: No. All code ships in the package.

**Data collected** (tick these)
- Personally identifiable information: name and email address from the user's Buffer account.
- Authentication information: Buffer sign-in tokens.

Both stay in the browser's extension storage and are sent only to Buffer. Leave the other categories unticked: scroll distance is held in memory and never stored or sent, and page content is not read.

**Certifications** (tick all three)
- Data isn't sold to third parties.
- Data isn't used or transferred for purposes unrelated to the item's single purpose.
- Data isn't used or transferred to determine creditworthiness or for lending.

## Before you submit

1. Create the item as a draft first and upload the zip (`pnpm zip`, output in `.output/`), visibility **Unlisted** for the early submission.
2. **Check the extension ID the store assigns.** The sign-in and refresh pages hard-code `ecmbcebdlcbhgggjgdnokhlllblbongm` (`site/callback.js`, `site/refresh.js`). If the store gives a different ID, update both files and the Buffer redirect settings. If the dashboard shows a public key for the item, putting it in the manifest `key` keeps the ID stable for local testing.
3. Test the packaged build from a clean profile: connect, refresh (wait for a token to expire), allow a channel site, scroll for a nudge, drag, nap, disconnect.
4. Re-read the Privacy tab answers against the manifest before submitting.
5. The name is just "Sproutling", but the summary and description mention Buffer. That is descriptive use; check with the team if unsure.
